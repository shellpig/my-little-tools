# P1 — 開發設計方針

> Phase：**P1 — 多關卡（Levels）**
> 本文件是 P1 的實作契約：資料格式、模組、儲存 key、接線與必要的技術決策。完成條件見 `實作規格.md`。

最後更新：2026-10-11

---

## 1. 共通決策

- **換關＝重新載入頁面。** `main.js` 在模組開頭讀出目前關卡，用它初始化地圖，整頁只建一次場景。開始新小鎮、讀取存檔、匯入檔案都是「寫好儲存 → `location.reload()`」。不寫場景拆除邏輯。
- **目前進度只存一個 key。** 關卡 id 與佈局一起存在 `small-town:game`（`{ level, layout }`），一次 `setItem` 寫完；寫入失敗就不 reload，原進度不變，不會出現新關卡配舊佈局。
- **一切道路都在網格上。** 網格格寬 `CELL = 1.6`（一條馬路寬），原點對齊大街。關卡道路、編輯模式鋪的路、汽車路網、平交道都以格子為單位。
- **行人走半格網格。** 行走網格格寬 `HALF = 0.8`（＝人行道寬），對齊同一原點。
- **第 1 關回歸。** 搬資料時保留建鎮的呼叫順序與 `rand()` 的取用順序，讓牆色、燈光熄滅時間等和現在一樣；唯一刻意的差別是後街北移 0.8。
- 不新增建置工具；新檔一律是 ES module。
- 字串替換式的修改用腳本做時，每處斷言只出現一次。

## 2. 檔案結構

```text
small-town/
  levels/
    index.js        LEVELS 清單與 levelById()
    town.js         第 1 關「小鎮」
    station.js      第 2 關「火車站」（P1-D）
  residents.js      第 1 關的居民（town.js 引用）
  assets/train-kit/ Train Kit 的 GLB、Textures、Previews（P1-C）
```

## 3. 關卡資料格式（各 Subphase 逐步補齊）

```js
export default {
  id: 'town', name: '小鎮', blurb: '一條大街、旅館與公園的安靜小鎮。',
  preview: 'levels/town.jpg',                        // P1-B
  bounds: [iMin, iMax, jMin, jMax],                   // 地圖範圍（格）＝可編輯範圍；邊緣的馬路格是車流出入口
  roads: [[i0, j0, i1, j1], ...],                     // 直線馬路段（同 i 或同 j）
  walks: [[i0, j0, i1, j1], ...],                     // 預鋪人行道格（廣場）
  paths: [[x0, z0, x1, z1], ...],                     // 不在網格上的步道（巷子等），世界座標矩形
  zebras: [{ x, z, w, ns }, ...],
  bus: { from: [i, j], stop: [i, j], to: [i, j], riders: ['旅館', '便利商店'] } | null,
  buildings: {...}, park: {...} | null, gas: {...} | null, parking: true | false,   // P1-A2
  residents: [...], commuters: 0, walkers: 20, strollers: 7,                          // P1-A2 / P1-D
  cats: [[x, z], ...], wishes: true | false,                                          // P1-A2
  rail: null,                                                                         // P1-C
  camera: { target: [x, y, z], position: [x, y, z] },
};
```

## P1-A1 — Grid Roads & Traffic

### 道路

- `bounds` 同時是可編輯範圍：畫筆在範圍外一律顯示紅框、不能鋪。關卡道路要通到外界的，直接畫到範圍邊緣。
- 關卡 `roads`／`walks` 展開成預設 tiles（`"i,j" → 'road' | 'walk'`）。佈局有 `#tiles` 時以它**整份取代**預設；沒有時用預設。`currentLayout()` 只在 tiles 與預設不同時寫出 `#tiles`。
- 刪除舊的街道特例：`STREETS` 的路面繪製、`halfCell`、街道延長 key（`s<k>,<i>`）、`paveable` 對街道列的限制、`streetSpan`、`paintStreet`。所有馬路格一律用 `pieceFor(roadSides(i, j))` 選 Kenney 路片。
- `roadSides()` 只看相鄰馬路格；地圖邊緣（`bounds` 外側）有路通出去的那一側視為開口（路片畫成直通）。

### 自動人行道

`paveSidewalks()` 改為依 tiles 生成：

- 每格馬路、每個沒接馬路的側邊：在格外鋪一條 `CELL × SIDEWALK` 的人行道，沿邊放路緣；邊界外側開口不鋪。
- 外角：同一格相鄰兩側都有人行道 → 補 `SIDEWALK × SIDEWALK` 角塊。
- 內角：兩個正交鄰格是馬路、對角格不是 → 在對角格靠內的角補角塊。
- 人行道與 `walk` 格重疊時照鋪（同材質）；要求的是視覺上無縫、無異常，不要求幾何上不重疊。
- 建築列仍以「道路中心 ± `FRONTAGE`」定位，`FRONTAGE = ROAD_HALF + SIDEWALK` 不變。

### 汽車路網

- `buildRoads()`：節點＝每格馬路（`"i,j"`），連結相鄰馬路格；`bounds` 邊緣有開口的側邊連到 `'exit'`。刪除 `s<k>,<i>` 街道節點與 `STREET_ENTRY`／`STREET_EXIT`。
- 進場：所有 `'exit'` 側都是入口；等待中的車隨機挑一個入口進場。進場點不在邊緣，而是從入口沿路往內，停在「離鏡頭預設目標 ≤ `FOG_R` 的第一格」的前一格（霧邊）；途中遇到路口就停在路口前一格。進場點的節點沒被佔住、附近淨空才放車。`FOG_R` 先取 11（等同舊的 `ROAD_END`）。
- 路口獨佔、排頭才搶路口、跟車錐形、斑馬線停讓、死路迴轉：沿用現有 `Vehicle` 寫法。
- 公車：建路網後用 BFS 算出 `bus.from → bus.stop → bus.to` 的節點序列，`Bus.chooseExit` 依序列走；到站判定改為「沿路徑的剩餘距離」，取代 `STOP_X`。`unloadBus` 的車門位置＝車身前段、行進方向右側路緣。
- 公車路線算不出來（被編輯切斷）時不發車；`buildRoads()` 每次重算，通了就恢復。已在路上的公車照一般車輛規則處理（節點消失就離開）。

### 第 1 關道路資料

- `bounds`：`i = -18…18`（x 約 ±29，在人行道範圍內）；`j` 涵蓋後街北側到公園南側。
- 大街：`j = 0`，`i = -18…18`；後街：`j = -5`（z = -8.0），`i = -18…18`；兩條街都畫到範圍邊緣，兩端即出入口，±12 以外藏在霧裡。
- 巷子不是馬路，寫成 `paths`；巷子與兩街的斑馬線寫在 `zebras`。
- A1 期間行人仍用舊邏輯：暫留 `STREETS = [0, -8.0]` 供路人、居民 `route()` 使用，P1-A2 移除。

### 舊存檔遷移

- 佈局加版本欄位 `'#v': 2`。遷移是純函式 `migrateLayout(layout) → layout`，本身不寫任何儲存；讀到沒有 `#v` 的佈局（自動存檔、存檔欄位、匯入檔）時先轉換再使用：
  - 建築／路燈／新增物的狀態若 `z < -3.6`：`z -= 0.8`。
  - `#tiles`：`z < -3.6` 的格子、`bounds` 外的格子、街道延長 key（`s<k>,<i>`，兩街已畫到邊緣）都刪除；其餘照搬。遷移後的 tiles 要併入第 1 關的預設道路（舊佈局的 `#tiles` 只記玩家鋪的格子）。
  - `#zebras`：`z < -3.6` 且 `ns: false` 的 `z -= 0.8`；`ns: true` 的刪除。
- 由呼叫端決定寫到哪裡，各寫各的：
  - 目前進度（舊 `small-town:layout`）：轉換後寫入 `small-town:game`，避免重複遷移；舊 key 不刪。
  - 存檔欄位（P1-B 搬移舊三格）：轉換後只寫 `small-town:slots`，**不碰** `small-town:game`。
  - 匯入檔：轉換後只在記憶體中，確認匯入成功時才寫 `small-town:game`。

## P1-A2 — Pedestrian Paths & Town Level Data

### 行走網格

- 範圍＝`bounds` 換算成半格；每個半格有通行代價：

  | 半格 | 代價 |
  |---|---|
  | 人行道、`walk` 格、`paths` 範圍內 | 1 |
  | 斑馬線覆蓋的馬路半格 | 1 |
  | 其他馬路半格（臨時穿越） | 25 |
  | 建築等 `solids` 覆蓋、地圖外 | 不可走 |
  | 其他（草地等） | 不可走 |

- tiles、斑馬線或建築變動後（`settleTown()`）重建網格並清空路徑快取。

### 找路

- 門口（`PLACES`、住家門）吸附到最近的可走半格。
- A*：8 方向、octile 距離；不准斜穿兩個不可走半格的夾縫。
- **嚴格優先斑馬線**：第一輪把「其他馬路半格」視為不可走；找不到路才跑第二輪，允許代價 25 的臨時穿越。
- 兩輪都找不到（斷路、建築被圍住）：回傳「到不了」。
- 結果轉世界座標點列，去掉共線點；依居民的 `lane` 往路徑右側偏移 0～0.25，讓人錯開。
- 快取 key＝起點半格＋終點半格。
- `Resident.plan()` 的每段路改用 A* 結果；作息、時間驅動位置的寫法不變。刪除 `route()`、`BLOCK_SIDE`、`crossingsAt()`、`walkZ()`。
- `plan()` 依序追蹤「實際所在地點」`at`：每段從 `at` 找路到作息指定的地點。
  - 找得到：該段 `to` 為目的地，走完後 `at = to`。
  - 到不了：該段標記 `stuck: true`、`to = at`、`pts = [at.door]`，`at` 不變，也就是留在原地、不出現；下一段仍從 `at` 出發。
  - 第一段的起點是「前一天最後一段結束時的 `at`」：先以家為起點算一輪得到結束地點，再用它當起點算第二輪。
- 因為 `leg.to` 一律是實際所在地點，`update()` 的公園分支只有真的走到公園才會觸發，不需另外改。
- `settleTown()` 重算時路通了就自動恢復。

### 路人與散步者

- `Walker`：在可走半格中隨機挑一個距離 4～12 的目標，A* 走過去（到不了就重挑，最多 5 次，仍失敗則原地停一下再試），偶爾停在商店前看櫥窗（沿用現有機率），到了再挑下一個；夜間依 `rank` 回家（走向最近的門口後消失）。
- `Stroller`：只在 `park` 存在時建立，行為不變。

### 關卡資料化

- `main.js` 頂端的地圖常數（`HOMES`、`SHOPS`、`CIVIC`、`HOTEL`、`PARK`、`GAS`、`CAT_SPOTS`、`LAMPS`、`WALKERS`、`STROLLERS`、`ALLEYS`、`DEFAULT_ZEBRAS`）改由 `LEVEL` 提供；建築列（`MAIN_NORTH` 等）改在 `levels/town.js` 內計算後提供。
- `park`、`gas`、`bus`、`hotel` 為 `null` 時跳過對應建造；依賴它們的東西（公園長椅的人、加油站地點、公車與乘客）一併跳過。
- 居民作息裡的地點若不存在，視同在家（沿用已刪除建築的處理）。

### 目前關卡與儲存 key

```js
import { levelById } from './levels/index.js';
const GAME_KEY = 'small-town:game';
const game = readGame();                  // { level, layout }；讀不到 → { level: 'town', layout: 舊 layout 或 {} }
const LEVEL = levelById(game.level);      // 不存在 → 'town'
```

| key | 內容 | 遷移 |
|---|---|---|
| `small-town:game` | 目前進度 `{ level, layout }`（A1 起使用） | 沒有時讀舊 `small-town:layout`（套 A1 遷移）、`level: 'town'`；舊 key 不刪 |
| `small-town:cats:<levelId>` | 該關的整份 `catBook`：找到的貓、祝福收集、投幣次數 | 舊 `small-town:cats` 整份讀進 `cats:town`；舊 key 不刪 |

### 許願與貓的開關

- `LEVEL.wishes === false`：不呼叫 `addWishes()`，`wishes` 維持未建立；**所有 `wishes` 呼叫點都要處理**——目前是初始化、點選物件清單（`wishes.clickables()`）、點噴水池丟硬幣、按 E 丟硬幣、每幀 `wishes.update()`；另外隱藏面板祝福區，噴水池附近不顯示許願的互動提示。動工時先 `grep -n "wishes\." main.js` 核對清單。
- `LEVEL.cats.length === 0`：不建貓、面板隱藏貓咪區；計數分母用 `LEVEL.cats.length`。

## P1-B — New Town Menu & Save Slots

### UI

- 左側按鈕列加「🏘 開始新小鎮」，開啟關卡選單（全螢幕遮罩＋卡片）。卡片：預覽圖、名稱、說明、「開始」。按開始 → `confirm('開始新的「<名稱>」？目前未存檔的變動會消失。')` → 寫入 `small-town:game = { level, layout: {} }` → 成功才 reload。
- 第 1 關預覽圖在本 Subphase 拍好：640×360 截圖存成 `levels/town.jpg`。
- 存檔面板沿用 `#slots`，改成 10 格的捲動清單；每格：快照（160×90 顯示）、「關卡名 · 時間」、`存到這裡`、`讀取`。

### 存檔格式

| key | 內容 |
|---|---|
| `small-town:slots` | 長度 10 的陣列；每格 `null` 或 `{ savedAt, level, layout, shot }` |

- `shot` 是 JPEG data URL（約 320×180、品質 0.7，約 15 KB）。
- 遷移：沒有 `small-town:slots` 而有舊 `small-town:layout-slots` 時，舊三格搬到第 1～3 格（`level: 'town'`、`shot: null`、佈局套 A1 遷移），其餘補 `null`；舊 key 不刪。
- 讀取：寫入 `small-town:game = { level, layout }` → 成功才 reload。同關卡也 reload。
- 所有寫入都包 try/catch：存檔欄位寫入失敗 → `alert('存檔失敗：瀏覽器儲存空間不足或無法使用。')`，欄位內容不變；`small-town:game` 寫入失敗 → `alert('無法切換：瀏覽器儲存空間不足或無法使用。')`，不 reload，畫面與儲存都維持原進度。

### 快照

- 另建一台俯視 `PerspectiveCamera`，從 `LEVEL.camera.target` 上方固定高度往下拍，渲染到 320×180 的 `WebGLRenderTarget`（不經後製），`readRenderTargetPixels` 轉 canvas 再 `toDataURL('image/jpeg', 0.7)`。
- 拍照時暫時隱藏選取框、畫筆標記，拍完還原。

### 匯出／匯入

- `LAYOUT_FILE` 版本升為 2，內容加 `level`。
- 匯入：`version` 1 或沒有 `level` → `'town'`（佈局套 A1 遷移）；`level` 不在清單 → 提示「這個佈局檔的關卡不存在」。成功＝寫入 `small-town:game` → 成功才 reload。

### 還原成預設

寫入 `small-town:game = { level: 目前關卡, layout: {} }` → 成功才 reload。

## P1-C — Railway & Trains

### 鐵道資料

```js
rail: {
  cells: [[i, j], ...],          // 依序相連的格子（含轉彎），兩端在 bounds 邊緣
  station: { cell: [i, j], side: 'east' } | null,   // 月台在哪格的哪一側
  every: [90, 240],              // 班次間隔（遊戲秒）範圍
  train: ['train-locomotive-passenger-a', 'train-carriage-...', ...],
}
```

- 鐵道走在網格上，與馬路格同一格時就是平交道；鐵道格不可同時是 `walk` 格。
- 軌道視覺：直線格用 `railroad-straight`、轉彎格用 `railroad-corner-small`；比例在第一次接素材時量測後寫成常數。

### 火車

- 由鐵道格算出一條連續中心線（直線段＋轉彎圓弧），火車沿弧長前進；每節車廂取自己中心的位置與切線。
- 速度控制沿用車子的「目標速度＋加減速上限」：進站等減速停在月台、停靠 `DWELL` 秒；前方有玩家站在軌道上時停等。
- 夜深（`activity(time)` 低）時班次間隔拉長。

### 平交道

- 鐵道格與馬路格重合處各放一組柵欄（方塊拼成：柱子＋紅白橫桿），位置在該格馬路的兩側人行道。
- 火車前端距平交道小於 `WARN` 或車尾尚未離開時，平交道關閉：橫桿放下（旋轉動畫）。
- 汽車：該路網節點在關閉期間當作被佔住的路口——沿用 `drive()` 中路口 `blocked` 的煞車寫法，多一種「平交道關閉」的阻擋來源。
- 行人：路徑不因柵欄重算，改成每幀檢查——行人下一步要踏進**關閉中**平交道的半格、而目前不在平交道上，就原地停下等；已經在平交道半格上的人繼續走完離開。柵欄升起後照原路徑繼續。
- 居民的位置由時間驅動，停等期間把該段的進度暫停（停等的時間不計入行走距離），避免柵欄升起後瞬移。

## P1-D — Station Level & Closeout

### 第 2 關資料（`levels/station.js`）

- 街道結構與第 1 關不同（例如南北向主街加東西向支路的 T 字、十字組合），確切形狀開工時在瀏覽器裡擺好再寫入。
- 鐵道穿過地圖中央，至少一處平交道；車站與月台在中央，站前廣場用 `walks`。
- 建築：便當店、車站旅店、便利商店、伴手禮店與住家；`park: null`、`gas: null`；公車站在站前廣場旁。
- `cats`：4～6 處（月台長椅下、廣場花台等）；`wishes: false`。
- `residents: []`；`commuters: N`：不具名通勤客，從車站出入口走到隨機建築門口（或反向）後消失，行為同 `Passenger` 但路線用 A*；火車到站時一次產生數名。
- 車站本體用商業建築模型加方塊（雨棚、月台、站名招牌）拼成，招牌沿用 `decorateShop` 的做法。

### 選單預覽圖

拍一張 640×360 截圖存成 `levels/station.jpg`（第 1 關的 `town.jpg` 已在 P1-B 交付）。

### Closeout

完成測試指南 P1-D 全部項目後，更新 `PROJECT_BRIEF.md` 的進度表與已知限制。
