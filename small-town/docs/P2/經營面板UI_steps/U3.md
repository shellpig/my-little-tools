- 日期：2026-10-13；worker：agy / Gemini 3.8 Flash (High)。
- 起始：`feat/small-town-ops-ui` @ U2 commit。
- 使用者需求：運行班表除了目前「點格子開視窗」的方式，也可以用拖拉設定時間表。
- 範圍：`main.js` 的 `setupOpsPanel()` 裡 `renderFleetList()`、`renderTimetable()`、班次視窗的「清除」「確定」處理；`index.html` 少量 CSS 與班表上方的提示文字。

## 指揮者裁定

1. **拖拉方式**：用 HTML5 drag and drop（`draggable`、`dragstart`／`dragover`／`dragleave`／`drop`／`dragend`），只支援滑鼠；觸控維持點格子開視窗。點格子開視窗的既有行為不變。
2. **兩種拖拉來源**：
   - **車隊卡片 → 格子**：把車隊清單的某台車拖到班表格子，排上這台車、停站（`stop: true`）。卡片上的車名輸入框與「出售」按鈕照舊可用（拖拉從卡片其他地方開始；輸入框本身設 `draggable=false`）。卡片加一個小抓把記號「⠿」與 `title="拖到班表格子排班"`。
   - **已排班格子 → 另一格**：把已排班的格子拖到另一格，等於「移動」這個班次：同一台車、保留原本的停／過，原格清空。拖回同一格什麼都不做。
3. **目標格已有別的車**：視為「取代」——先把目標格原本的班次拿掉，再檢查能不能排。移動時也先拿掉來源格。
4. **檢查**：用既有 `canAssignTrain(fleet, 去掉上面兩格之後的班表, hour, dir, trainId, stop)`。不合法時不改任何東西，`showToast(\`無法排班：${reason}\`)`。合法時寫入新班表。
5. **拖拉中的提示**：拖到格子上時（`dragover`）即時用同一個檢查決定外觀：合法加 class `drop-ok`（綠框），不合法加 `drop-bad`（紅框）；`dragleave`／`drop`／`dragend` 清掉。拖拉中的資料（來源是車還是格子、trainId、來源格、stop）存在 `setupOpsPanel()` 內的一個變數，不靠 `dataTransfer` 讀（`dragover` 讀不到內容）；`dataTransfer.setData('text/plain', …)` 仍要呼叫，Firefox 才會開始拖拉。
6. **共用寫入**：把「寫入班表 → `rail.setTimetable()` → `saveLayout()` → `renderTimetable()`」抽成 `setupOpsPanel()` 內的一個小函式（例如 `commitTimetable(next)`），讓視窗的「確定」「清除」與拖拉共用；視窗關閉（`hidden = true`）留在原處理裡。不改 `canAssignTrain()`／`validateTimetable()`。
7. **提示文字**：班表標題下方加一行小字（`var(--dim)`）：「點格子設定，或把車隊卡片、已排班的格子拖到格子上」。
8. 第 1 關沒有經營面板，不受影響。

## 驗收

- `node --check main.js`。
- 瀏覽器（第 2 關，以 Playwright 的 `dragTo` 或派送 DragEvent 驗）：
  - 把「普通 2 號」卡片拖到空的 10:00 往東：該格變「普通 2 號 · 停」，`p2State.timetable` 多一筆，存檔。
  - 把 9:00 往西（普通 2 號）拖到 11:00 往西：9:00 清空、11:00 出現且停／過不變。
  - 拖到會違規的格子（例如間隔不足）：拖拉中紅框，放下後跳「無法排班：…」、班表不變。
  - 點格子仍開視窗；視窗的確定、清除照舊。
- 第 1 關主控台無錯誤。
