## 指揮者裁定的契約疑點

1. **沿用說話泡泡，不新增標籤元素**：照 `fountainVoice` 的寫法建一個 `stationVoice = { obj: <車站的 editable pivot>, bubbleY: <車站高度 + 0.1> }`，用既有 `talk(stationVoice, { name: STATION.name, role: '車站', line })` 顯示。泡泡位置、隱藏邏輯全部沿用 `updateTalk()`。車站被刪除時 pivot 不可見，泡泡自然收掉。
2. **只在第 2 關**：`LEVEL.atrain && STATION` 才建 `stationVoice`、才做 hover／點擊判斷；第 1 關完全不跑新程式。
3. **文字**：`p2State.ledger` 有資料時 `昨日乘客 N 人`（N＝最後一筆 `riders`）；空的時 `昨日乘客 —（還沒有結算）`。
4. **點擊**：既有 pointerup 裡，原本的 `targets` 都沒打中時，再對車站 pivot 做遞迴 raycast（`intersectObject(pivot, true)`）；打中就 `talk(...)`，維持 5 秒（`talk()` 預設）。人、貓、噴水池優先。
5. **滑鼠移過**：既有 pointermove 裡，非編輯模式、非散步模式（`player.active`）時對車站 pivot 遞迴 raycast；打中時若泡泡不是車站的就 `talk(...)`，是車站的就把 `talkUntil` 延到 `performance.now() + 800`，移開後約 0.8 秒消失。pointermove 只在 `LEVEL.atrain` 時做這個 raycast。
6. **高度**：`buildStation()` 完成後，用 pivot 的 `Box3` 高度算一次 `bubbleY`；之後不重算（搬動車站高度不變）。
7. 編輯模式不顯示（pointerup 原本就在 `editing` 時 return；pointermove 加同樣條件）。

## 驗收

- `node --check main.js`。
- 瀏覽器（第 2 關）：滑鼠移到車站上出現泡泡「晴川站 車站／昨日乘客 …」，移開消失；點車站泡泡停留約 5 秒；結算後數字等於 `ledger` 最後一筆 `riders`；新小鎮顯示「還沒有結算」。點路人仍是原本的對話。
- 第 1 關：點路人、貓、噴水池行為不變，主控台無錯誤。
