## 指揮者裁定的契約疑點

1. **數字來源**：人口 `population()`、住宅 `homeCount()`（含透天、別墅、小公寓）、商店 `shopCount()`。不另寫計數。
2. **金額格式**：把 `advanceClock()` 裡 toast 用的「四捨五入到 0.1、整數不帶小數」抽成 `formatMan(n)`（回傳絕對值字串，不含正負號與「萬」），toast 與小鎮分頁共用。toast 文字不變。
3. **昨日明細**取 `p2State.ledger` 最後一筆，五列：火車 `+income.rail`、公車 `+income.bus`、設施 `+income.facility`、營運費 `−cost`、淨額（三項收入 − 營運費，正數 `+`、負數 `−`，負數用紅字，沿用 `.money.negative` 的 `#ff6b6b`）。標題「昨日（第 N 天）」，N＝該筆 `day`。`ledger` 是空的時整塊只顯示「還沒有結算，每天 06:00 結算」。
4. **折線**：純 SVG（`document.createElementNS`），不加函式庫。點＝`ledger` 每筆的 `balance`，依序由左到右，最多 7 點；`viewBox="0 0 240 90"`、寬 100%。y 依這幾點的最小～最大值縮放並留上下邊距；最小等於最大時畫在中間一條水平線。每點畫小圓點；左上標最大值、左下標最小值（`formatMan` 加「萬」，負數加「−」）。0 筆不畫折線，1 筆只畫一個點。線色 `var(--accent)`。無限資金時 `balance` 就是當時的資金，照畫，不特別處理。
5. **刷新時機**：切到「小鎮」分頁時（既有 `renderOpsPanel()`）、以及每次結算後。結算在 `setupOpsPanel()` 外面，照 `updateFleetLiveStatus` 的掛法：模組層 `let refreshTownTab = null;`，在 `setupOpsPanel()` 裡指定為「面板開著且目前是小鎮分頁時呼叫 `renderTownTab()`」；`advanceClock()` 結算區塊最後呼叫。編輯模式蓋房子造成的人口變化不即時刷新，切回分頁或下次結算才更新。
6. **版面**：`#ops-town-tab` 由上而下：三格統計（人口／住宅／商店，數字大、標籤小）→ 昨日明細 → 「最近 7 天資金」折線 → 既有的自動成長開關與速度（不動）。沿用面板既有的 `.opt-label` 與 inline style 口吻；新 CSS 只加必要幾條。
7. **第 1 關**：沒有經營面板，不受影響。

## 驗收

- `node --check main.js atrain.js`。
- 瀏覽器（第 2 關）：
  - 開「經營 → 小鎮」：三個數字和主控台 `population()`／`homeCount()`／`shopCount()` 相同（指揮者用臨時除錯手段讀）。
  - 新小鎮（`ledger` 空）顯示「還沒有結算」。
  - 跳過幾次 06:00 結算後：明細四項加總等於淨額、等於 toast 數字；折線點數等於 `ledger.length`（最多 7）。
  - 面板開在小鎮分頁時跨過 06:00，數字與折線自動刷新。
- 第 1 關主控台無錯誤。
