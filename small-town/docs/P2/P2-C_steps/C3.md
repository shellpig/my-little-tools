## 指揮者裁定的契約疑點

1. **門面**：設施 pivot 朝向的 +z 那一邊（模型正面），隨 R 旋轉。compose 類同樣用 +z 邊。
2. **接路判定**：門面邊（線段）到任一 `sidewalkRects()` 矩形的最短距離 ≤ 0.3 才算接路。十種設施都要接路才生效（賺錢類才有收入、公寓與辦公才有人口；裝飾類的成長加分到 P2-D 才用）。
3. **重算時機**：不另存快取，需要時現算（`facilityLinked(item)`）：放下、搬動或旋轉後、undo 後、鋪路一筆結束後、結算與人口計算時。結果不存檔。
4. **提示**：放下或搬動／旋轉一個設施後，若沒接路就 `showToast('沒有接到道路')`；選取沒接路的設施時同樣提示一次。
5. **影響範圍圈**：只有表裡有 `radius` 的設施（工廠 6、小公園 6、廣場地標 8；單位是格，乘 `CELL`）在放置中與選取時，在地面畫一個半透明圓；接路時綠色、沒接路時紅色。其他設施不畫圈。取消選取或放下別的東西時隱藏。
6. **結算**：`settle(state, counts, pop, kinds)` 多一個參數 `kinds`＝已接路設施的 key 陣列（沒被刪除）。`income.facility` ＝ 各設施 `daily`（商店是函式，代入總人口）加總，旅館另加 `perStop × 當天停站班次數`。純函式，不讀場景。
7. **人口**：`population()` 加上已接路公寓 +40、辦公大樓 +80（取表裡的 `pop`）。商店收入用的人口就是這個總人口。
8. **第 1 關**：沒有設施，不受影響。
