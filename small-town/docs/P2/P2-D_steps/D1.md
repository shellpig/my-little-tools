## 指揮者裁定的契約疑點

1. **`growth` 欄位**：`{ on: true, speed: 'normal', cooldown: {} }`。`normalizeP2()` 欄位缺少或不是物件時整個補預設；有物件時逐欄補：`on` 不是布林補 `true`，`speed` 不在 `GROWTH_SPEEDS` 裡補 `'normal'`，`cooldown` 不是物件補 `{}`。
2. **速度**：`GROWTH_SPEEDS = { slow: 1, normal: 2, fast: 4 }`（每天棟數），面板標籤「慢／一般／快」。
3. **`lotScore(lot, ctx)` 是純函式**，不讀場景，所有場景資訊由呼叫者（D3）算好放進參數：
   - `lot = { x, z, cell, neighbour }`：地塊中心（世界座標）、地塊所貼的馬路格 key（`'i,j'`）、左右鄰地塊是否已有房子。
   - `ctx = { cell, station, stops, busCells, facilities }`：`cell` 是一格的世界長度（main.js 的 `CELL`）；`station = { x, z }`；`stops` 是前一天停站班次數；`busCells` 是公車路線經過的馬路格 key 的 `Set`，沒有公車時是 `null`；`facilities = [{ x, z, radius, growth }]`（`radius` 單位是格，只放已接路、沒被刪除、表裡有 `growth` 的設施）。
4. **分數**（距離一律是地塊中心到對象中心的直線距離，`≤` 算在內，以格計＝距離 ÷ `ctx.cell`）：
   - 基本 2（鄰路是地塊的前提，`lotScore` 不再檢查）。
   - 車站：`stops > 0` 時，12 格內 +3，否則 24 格內 +1；`stops >= 6` 且在 24 格內再 +1。`stops === 0` 車站不加分。
   - 公車：`busCells` 不是 `null` 且含 `lot.cell` → +2。
   - 設施：每個 `facilities` 在 `radius` 格內就加它的 `growth`（小公園 +2、廣場地標 +2、工廠 −2），可疊加。實作規格寫「+2～+4 依設施」，以 `FACILITIES` 表的數值為準（目前都是 +2），不另加。
   - `lot.neighbour` 為真 +1。
   - 回傳總分（整數）。合格門檻 5 與加權抽籤是 D3 的事。
   - 匯出常數 `GROWTH_MIN_SCORE = 5`，D3 用。
5. **面板**：「小鎮」分頁（`data-tab="town"`）內容：「自動成長」勾選框、速度 chips「慢／一般／快」（目前那個是 `on`）。改動立即寫進 `p2State.growth` 並 `saveLayout()`。關掉時速度 chips 仍可點。P2-E 會在同一分頁加人口等資訊，本步不做。
6. **第 1 關**：沒有經營面板，不受影響。

## 驗收

- `node --check` 所有改動 JS。
- Node 驗 `lotScore()`（`cell = 1.6`，車站在原點）：
  - A：地塊 (8, 0)（5 格）、停站 4、公車路線含其格、小公園 (8, 3)、鄰屋 → 2 + 3 + 2 + 2 + 1 = 10。
  - B：同 A 但停站 6 → 11；停站 0 → 7。
  - C：地塊 (30, 0)（18.75 格）、停站 6、沒有公車、工廠 (30, 4) → 2 + 1 + 1 − 2 = 2。
- `normalizeP2({})` 的 `growth` 是預設；`normalizeP2({ growth: { on: false } })` 保留 `on: false` 並補其他欄位。
- 瀏覽器：第 2 關經營面板「小鎮」分頁可切換，開關與速度改動後重新整理仍保留。
