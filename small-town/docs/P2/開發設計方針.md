# P2 — 開發設計方針

> Phase：**P2 — 輕量 A 列車（Light A-Train）**
> 本文件是 P2 的實作契約：資料格式、模組、儲存、接線與必要的技術決策。完成條件見 `實作規格.md`。

最後更新：2026-10-12

---

## 1. 共通決策

- **只有第 2 關啟用經營模式。** 關卡資料多一個 `atrain: true`；`main.js` 的經營功能全部以 `LEVEL.atrain` 判斷，第 1 關走原本的路。
- **經營狀態放在佈局裡。** 存檔欄位存的是 `{ level, layout }`，所以經營狀態寫成佈局的一個 key `#p2`，目前進度、10 格存檔、匯出入自動一起帶走，不新增 localStorage key。
- **建築類的新東西沿用「新增物件」機制。** 公共設施、自動長出的住宅與商店都是 `add` 物件（`buildAdded()`／`currentLayout()` 已會存），不另做一套建築系統。
- **數值與純邏輯集中在 `atrain.js`。** 車型、設施、價格、收入公式、成長分數、班表檢查都在這裡，是不碰場景的純函式與常數表，調數值只改一處。
- **遊戲時間是唯一時鐘（第 2 關）。** 移動、班表、結算都用遊戲時間；現實時間只拿來換算畫面。第 1 關照舊。
- 不新增建置工具；新檔一律是 ES module。字串替換式修改用腳本做時，每處斷言只出現一次。

## 2. 檔案結構

```text
small-town/
  atrain.js           車型表、設施表、價格、結算、成長評分、班表檢查（純函式）
  levels/station.js   多 atrain: true、預設車隊與班表、公車預設
  rail.js             改為車隊＋班表驅動（P2-A）
  main.js             倍速、經營面板、結算接線、設施放置、成長
```

## 3. `#p2` 佈局狀態

```js
layout['#p2'] = {
  v: 1,
  day: 0,                       // 已結算的遊戲日數；每過一次 06:00 加 1
  money: 5000,                  // 萬；可為負
  unlimited: false,             // 無限資金
  fleet: [{ id: 't1', name: '普通 1 號', type: 'local' }, ...],
  timetable: [{ train: 't1', dir: 'east', hour: 7, stop: true }, ...],
  buses: [{ color: 'green' }],  // 台數＝長度
  growth: { on: true, speed: 'normal', cooldown: { '<lotKey>': 解除的 day } },
  ledger: [{ day, income: { rail, bus, facility }, cost, riders, balance }, ...],   // 最多留 7 筆；balance＝結算後資金；riders＝當天各停站班次載客數加總
};
```

- 讀取：第 2 關佈局沒有 `#p2` 時，用 `levels/station.js` 的預設建一份（舊存檔遷移就是這一步）；有 `#p2` 時**逐欄**用預設補上缺的欄位（P2-A 的存檔到 P2-B／C／D 會缺新欄位）；`#v` 不變。第 1 關不讀也不寫 `#p2`。
- 當天累計（停站／不停站班次、載客）只在記憶體，不存檔；重新整理後從 06:00 重新開始（實作規格 P2-B 第 9 條）。
- `currentLayout()` 在 `LEVEL.atrain` 時一律寫出 `#p2`。
- 公共設施、自動長出的房子是 `add` 物件：`add.type` 為 `'facility'`（`add.kind` 是設施 key）或原有的 `'house'`／`'villa'`／`'shop'`，自動長出的另帶 `add.auto = true`、`add.lot = '<lotKey>'`、`add.born = day`。

## P2-A — Time Scale & Timetable

### 倍速

- `speed` 的內部值不變（60／600／3600），只改按鈕文字為 1×／10×／60×，說明改成「1× 為每秒經過一分鐘」。
- 新增 `rate = LEVEL.atrain ? speed / 60 : 1`（第 2 關為 1、10、60；**第 1 關恆為 1**，行為不變）。第 2 關所有「以現實秒計」的移動改吃 `dt * rate`：`Vehicle`／`Bus`、`Walker`、`Commuter`、`Passenger`、貓、玩家以外的動畫。玩家（散步模式）與鏡頭不受倍速影響。
- **子步：** 每幀把 `dt * rate` 切成不超過 0.1 秒的小步，逐步呼叫各更新；10× 時約 2 步。
- **略過模式（第 2 關 60×）：** 汽車、公車、路人、通勤客、貓暫停更新並淡出不畫；切回時從現狀繼續（車輛在入口重新排隊，行人重新挑目標）。火車仍以子步模擬（只有 2～3 列，成本低），所以班表與平交道狀態連續。居民位置本來就由時間驅動，照常。

### 火車速度與時間換算

- 1× 下火車巡航 `TRAIN_CRUISE = 2.0` 單位／現實秒＝2 單位／遊戲分鐘；車型速度是它的倍數。
- 停站 `TRAIN_DWELL` 改為 6 遊戲分鐘。
- 「到站整點」換算進場時間：`進場 = 到站 − 進場點到車站中心的弧長 ÷ 巡航速度`（加減速忽略，誤差在 1 分鐘內可接受）。

### 車隊與班表（`rail.js`）

- `buildRail()` 的列車來源改成 `#p2.fleet`：每台車各自建一組模型實例（依車型的模型名單），平常隱藏；同車型兩台是兩組實例。
- 每台車有狀態：`at: 'west' | 'east'`（停在哪一頭）、`busyUntil`（離開地圖的時刻）、`run`（正在跑的那一班或 null）。
- 每遊戲分鐘檢查：班表中某班的進場時刻到了，就判斷：
  - 該車 `run` 不為空（還在跑）或 `at` 不是這班的出發端 → **取消**，記一筆取消（不收票、不扣營運費）。
  - 對應方向的軌道上還有前一列車沒離開地圖 → 在入口外**等待**，淨空後立刻進場（等待期間不算取消）。
  - 否則放車開跑；停不停站看該班的 `stop`。
- **回送：** 每天 03:00 檢查每台車：`at` 和它隔天第一班的出發端不同，就直接把 `at` 換過去並記一筆營運費，不產生畫面。
- 方向沿用現有雙線：往東走南線（`eastbound`）、往西走北線（`westbound`）。
- 跑完一趟：`at` 換到終點那一頭、`busyUntil` 記離開時刻、`run = null`。
- 移除舊的 `every`、`express.every` 隨機發車與 `activity` 拉長班距。

### 班表檢查（`atrain.js`）

`validateTimetable(fleet, timetable)` 回傳每一格可不可以選與原因：

- 同方向同一整點只能一班。
- 同一台車同一天的班次依時間排序後，方向必須東西交替；兩班之間的時間要 ≥ 該車跑完一趟所需時間（地圖全長 ÷ 速度＋停站時間）。
- 跨日不檢查方向（由回送處理），只檢查最後一班在 03:00 前離開地圖、第一班在 03:00 後進場；不符合就提示。

UI 只在選格子時呼叫它；載入舊存檔或資料被手動改壞時，不合法的班次保留但標紅、不發車。

### 車型表

  retro:   { name: '復古客車', units: ['train-locomotive-passenger-a', 'train-locomotive-passenger-b', ...], speed: 0.8, price: 1800, seats: 80, tourism: 1.5 },

### 經營面板

- 左側按鈕列在「編輯」下方加「🚆 經營」，只在 `LEVEL.atrain` 時顯示；開啟 `#ops` 面板（與新增面板同款樣式），分「火車／公車／小鎮」三頁（P2-A 只有火車頁）。
- 火車頁上半：車隊清單（名稱可直接改、車型、目前位置／狀態、出售），下方「買車」選車型。
- 火車頁下半：班表，24 列（整點）× 2 欄（往東／往西）。格子顯示車名與「停／過」；點格子跳出小選單：選車（只列可選的車，不可選的灰掉並顯示原因）、停或不停、清除。

## P2-B — Money & Daily Settlement

### 日結算

- 跨日只在主迴圈的自然推進判斷：`frame()` 把這幀的遊戲分鐘數（未取餘數）傳給 `advanceClock(minutes)`，它算出這段時間跨過 06:00 幾次，每次呼叫 `settleDay()`、`#p2.day += 1`（第一次結算後計數歸零，之後的日子計數為 0，照樣結算營運費等固定項）。
- `setTime()` 被滑桿或時段按鈕呼叫時（`continuous === false`）不結算、不累計。
- 每天累計：`stops`（停站班次與各自車型）、`passes`（不停站班次）、`runs`（總班次）；結算後歸零。
- `settle(state, counts) → ledgerEntry` 是 `atrain.js` 的純函式，照實作規格的公式算；`main.js` 把結果加進 `money`（無限資金時不動 `money`）、推進 `ledger`（留 7 筆）、跳通知。

### 人口

`population()`：一般住宅 4、別墅 3、`add.kind` 有 `pop` 的設施照表；被刪除（`removed`）的不算。數值放在 `atrain.js`。

### 花錢

- `spend(amount, what)`：無限資金時直接成功；資金 < amount 時提示「資金不足」並回傳 false；否則扣款。資金為負時一律不能花。
- 買車、賣車（`refund` 一半）在經營面板。
- 鋪路：畫筆一筆畫完（`endStroke()`）時比對前後 tiles，算出新增與清除的格數與種類，一次扣款；資金不夠時整筆撤銷並提示。斑馬線計入人行道價。
- **undo 反轉金額：** 每個會花錢或退錢的動作，把金額記在該 undo 步驟（`step.money = −spent` 或 `+refund`）；undo 時把 `step.money` 反向加回資金。鋪路、清除、刪除設施一律走這套；買車、賣車在經營面板，不進 undo。

### 標題列

標題下方顯示「資金 5,000 萬」或「資金 無限」；負數用紅字。通知用一個右上角小 toast，2 秒消失，可點。

## P2-C — Buses & Public Facilities

### 公車

- `#p2.buses` 的長度就是台數（上限 4）。`Bus` 改成可多台：06:00～23:00 之間每 (60 ÷ 台數) 遊戲分鐘發一班，由當時空著的那台出車（輪流），路線沿用 `LEVEL.bus`；沒有空車就等。
- 車身顏色：`BUS_COLORS` 6～8 色，改 `makeBus()` 的 `paint` 材質；每台一份材質。

### 公共設施

- 刪除退一半，undo 時照上面的規則扣回。
- 牆色：賺錢類的商用模型走 P1 的 `paintable()`。

## P2-D — Town Growth

### 地塊

- 從所有馬路格的每個「沒有接馬路的側邊」往外推 `FRONTAGE`，沿該側每 1.0 單位取一個地塊中心；門面朝路。`lotKey = "<i>,<j>,<side>,<k>"`。
- 地塊 footprint 約 1.0 × 1.2（依長出的模型實測）；檢查：不撞 `solids`、不碰鐵道格與月台、不在馬路／人行道／`walk` 格上、離 `bounds` 邊緣 ≥ 1 格、不撞玩家種的樹（`add.type === 'tree'`）與路燈。關卡預設的樹（`tree:N`）會被清掉（以 `removed` 狀態存）。
- 候選地塊只在結算時重算，每天最多評分 50 塊（隨機抽樣）。

### 分數與挑選

- `lotScore(lot, ctx)` 在 `atrain.js`，照實作規格的表；`ctx` 帶車站位置、昨天停站班次數、公車路線節點、設施清單（位置、半徑、加分）、鄰地塊是否有房。
- 合格（≥ 5）的地塊以分數為權重抽籤。商店與公寓升級規則照實作規格。

### 生成

- 長出的房子用 `buildAdded()` 建、`id = 'grow:<day>-<n>'`，`add.auto = true`。一天全部建完後只呼叫一次 `settleTown()`。
- **門口：** `buildAdded()` 建出的住宅、商店、公共設施都產生一個 `PLACES` 門口（門面中央往外 0.05），登記到 editable 的 `places`；`commuterDoor()` 與路人的目的地清單改成從所有未刪除的門口挑。搬動、刪除沿用 editable 的 `places` 同步。
- 長出動畫：pivot 的 y 縮放 0 → 1，0.6 秒（略過模式時直接完成）。
- 玩家刪除 `auto` 房子 → `growth.cooldown[lotKey] = day + 7`。
- 公寓升級：先用小公寓模型的 footprint 在原位置檢查空間（同地塊檢查），不通過就跳過。通過則原 `add` 物件改成 `removed`，在同位置建一棟 `add.type = 'facility'`、`add.kind = 'smallApartment'`（`FACILITIES.smallApartment`：`pop: 15`、`daily: 0`、不放大、玩家不能購買）、`add.auto = true`，id 沿用加 `-up`。
- 住宅總數（含 `HOMES`、新增、自動）達 300 時當天不長；當天名額只長到剛好 300。冷卻 `cooldown[lotKey] = day + 7`，`day <= cooldown` 期間不長。
- 商店數一律用 `shopCount()`：關卡 `SHOPS`、新增商店、`facility/shop`、自動商店，扣掉 `removed`。

## P2-E — Feedback & Closeout

- 「小鎮」頁：人口、住宅數、商店數、昨日明細（取 `ledger` 最後一筆）、7 天資金折線（純 SVG，不加函式庫）。
- 車站熱度：選取或滑鼠移到車站時，在車站上方的小標籤顯示昨日乘客數（`ledger.riders`）。
- 平交道鈴聲：WebAudio 合成（兩個方波交替），只在柵欄關閉期間、且鏡頭距平交道 < 40 時播放；標題列加一個 🔔／🔕 靜音開關，存在 `small-town:muted`（偏好，不進存檔）。
- 車頭視角（選做）：點選列車 → 鏡頭跟在車頭後上方，Esc 回原本視角。
- Closeout：跑完測試指南 P2-E，更新 `PROJECT_BRIEF.md`。
